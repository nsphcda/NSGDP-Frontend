## Specific corrections

These points in older documents do not match the code:

- **Reader language.** Older docs describe a Python reader container. The reader is TypeScript inside the worker. See [Pipeline stages](/docs/ingestion-stages).
- **Web framework.** Older docs name Fastify. The API is NestJS 11. See [Backend](/docs/backend).
- **Queue library.** Older docs name Bull v4. The queues use BullMQ with `@nestjs/bullmq`. See [Background jobs](/docs/background-jobs).
- **Worker process.** Older docs say the worker is not a separate process. It is: `dist/worker.js` with `ROLE=worker`, in its own container. See [Deployment](/docs/deployment).
- **Eight stages.** Older docs describe eight stages that include change-point and succession detection. The pipeline runs eight stages of its own. Succession and change-point are separate scheduled jobs. See [Pipeline stages](/docs/ingestion-stages).
- **Database.** Older docs name pgvector as unavailable in the deployed Postgres image. Check the current image before relying on either claim.
- **Dataset review.** Older docs describe one approval capability. The current model uses two tiers: `validate:datasets` and `approve:datasets`. See [Dataset lifecycle](/docs/dataset-review).

## Recommended reading order for a new reader

3. Older design documents only when a page here points to them
